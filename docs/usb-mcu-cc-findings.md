# SY108 USB、板载 MCU 与 CC/PD 硬件参考

本文汇总 SY108 板级的 USB 通路拓扑、板载协处理器（芯海 CS32G020）UART 通信协议、原厂 USB 模式切换逻辑及 SC2730 Type-C 寄存器特征。

---

## 一、板级硬件与 USB 拓扑

- **板载 MCU**：芯海科技 **CS32G020**（双通道 USB Type-C PD 控制器 / MCU），固件版本标识为 `SY108_MCU_V07`，通过 `/dev/ttySE1`（115200 8N1）与 UDX710 AP 通信，AP 侧 GPIO70/GPIO71 用于复位与唤醒控制。
- **双 Type-C 接口形态**：
  - **内口（直连手机侧）**：Type-C 公头，具备 SuperSpeed（SS）与 High-Speed（HS）引脚。
  - **外口（连接主机/电源侧）**：Type-C 母座，仅具备 High-Speed（HS）与供电引脚。
- **可达数据通路**：
  - 内口 SS 与外口访问模组的 HS 共用 UDX710 **USB1（`0x29100000`）** 控制器。
  - 板级还存在一条外口 HS 至内口 HS 的硬件切换通路：当内口经转接接入另一台 USB2 设备且处于特定 CC 极性方向时，板级开关会将外口 HS 直通至内口设备（此时模组自身的 USB1 NCM 从外口断开）。

```text
UDX710 USB1 SS (0x29100000) <--------------------------> 内口 Type-C (SS)

UDX710 USB1 HS (0x29100000) <----> 板级 HS 路由/开关 <----> 外口 Type-C (HS)
内口 Type-C (HS)            <---->        ↑
```

## 二、原厂 USB 配置与私有控制接口

### 1. 原厂设备树与接入检测
- **主系统 DTB**：启用 `usb1@29100000`，通过 SC2730 `EIC0`（VBUS 检测）绑定 `extcon_usb0`（无 ID 引脚输入）。
- **Recovery DTB**：`usb1@29100000` 接入检测绑定至 SC2730 `typec@380` extcon。
- **PMIC 与 I2C**：原厂 DTB 启用 `typec@380`、禁用 `pd@e00`；AP 侧 6 个 I2C 控制器均未启用，USB 路径切换由外部 CS32G020 自主控制并通过 UART 事件通知 AP。

### 2. 原厂 USB Gadget 模式表（`PRJ_SRT880.sh`）

| 模式编号 | 网络功能 | VID:PID | 调试接口组合（诊断 / AT / 日志 / ADB） |
|---:|---|---|---|
| `1` | NCM | `1782:4040` | 包含 |
| `2` | ECM | `1782:4039` | 包含 |
| `3` | RNDIS | `1782:4038` | 包含 |
| `4`（默认） | NCM | `3426:4005` | 不含 |
| `5` | ECM | `2dee:4d2c` | 不含 |
| `6` | RNDIS | `2dee:4d42` | 不含 |
| `7` | MBIM | `2dee:4d2b` | 不含 |
| `8` | NCM | `3426:4005` | 包含 |

### 3. 原厂内核 Gadget 私有 sysfs 属性与 EP0 厂商请求

| 属性名 | 功能说明 |
|---|---|
| `plugin` | 写入 `out` / `in` 触发 `dwc3_sprd_gpio_plug` 软插拔重枚举 |
| `odm_usb_wakelock` | 控制原厂 USB 唤醒锁状态 |
| `trigger_flag` | 手机附件识别就绪标志，参与 EP0 `0xC0/0x22` 响应判断 |
| `device_sleep_status` | 保存 AP/附件连接状态 |
| `simAction` | 保存 SIM 状态供附件信息查询读取 |
| `snNumber` | 保存 19 字节附件序列号 |

- **EP0 附件识别请求（`bmRequestType=0xC0, bRequest=0x22, wValue=0x01xx, wIndex=0`）**：当 `trigger_flag` 就绪时返回最多 41 字节附件信息（型号、序列号及 SIM 状态）。
- **EP0 模式切换请求（`bmRequestType=0xC0, bRequest=0x08 / 0x09`）**：触发内核向用户态 `notify` 进程发送 Netlink 消息（如消息 4 触发 `switch_usb temp 3` 切至 RNDIS 调试模式，消息 5 触发 `switch_usb const 8` 切至带调试口的 NCM 模式）。

## 三、CS32G020 MCU 串口协议与命令表

### 1. 普通帧格式（115200 8N1）

| 字节偏移 | 长度 | 字段说明 |
|---:|---:|---|
| `0` | 1 | 帧头固定 `0xAA` |
| `1` | 1 | Major 类型，普通通信固定为 `0x60` |
| `2..3` | 2 | 小端总帧长，等于 `payload_len + 7` |
| `4` | 1 | Minor 命令字（请求为 `0x01..0x0D`，应答/ACK 为高 4 位与低 4 位互换 `0x10..0xD0`） |
| `5` | 1 | Payload 字节长度 `N` |
| `6..6+N-1` | `N` | Payload 数据（注意：原厂发送函数会将调用方缓冲区按字节逆序发出，下表均按**实际线上字节序**描述） |
| `6+N` | 1 | 校验和：前 `6+N` 个字节累加和的低 8 位（`SUM8`） |

### 2. MCU 命令与事件表

| 功能 | 请求 / 应答 Minor | 登记长度 | 线上帧语义与行为 | 当前内核驱动（`sy108-mcu`）支持 |
|---|---|---|---|---|
| ADC 采样查询 | `01` / `10` | 4 / 4 | 请求 `[ch, 0, 0, 0]`；应答第 0 字节回显通道号，第 2..3 字节为 16 位小端原始值（通道 3..5 走 MCU ADC） | 已支持（IIO `in_voltage3..5_raw`） |
| GPIO 输出设置 | `02` / `20` | 2 / 2 | 请求 `[gpio, state]` | 未启用 |
| GPIO 输入读取 | `03` / `30` | 2 / 2 | 请求 `[gpio, 0]`，应答返回状态 | 未启用 |
| MCU 请求 AP 关机事件 | `04` / `40` | 0 / 0 | MCU 主动上报 `04`；AP 收尾后回复**零长度 payload** 的 `40` ACK 并执行关机 | 已支持（`event` / `event_ack`） |
| MCU 休眠设置 | `05` / `50` | 1 / 1 | 发送 1 字节休眠控制码 | 未启用 |
| 固件版本查询 | `06` / `60` | 0 / 64 | 请求无 payload；应答固定 64 字节版本字符串（如 `SY108_MCU_V07`） | 已支持（`firmware_version`） |
| AP 请求断电控制 | `07` / `70` | 1 / 1 | AP 主动下发电源控制码 | 未启用 |
| Nearby 状态查询 | `08` / `80` | 1 / 1 | 请求 `[0]`，返回附件在位状态 | 未启用 |
| USB 重连事件 | `0A` / `A0` | 1 / 1 | MCU 主动上报 `0A`；AP 回复 1 字节 `[0]` 的 `A0` ACK，并触发 USB1 Gadget 软重连 | 已支持（`event` / `event_ack`） |
| 升级后 OTG 检查 | `0C` / `C0` | 1 / 1 | 原厂 MCU 升级完成后下发，随后重启 AP | 未启用 |
| Modem 电源控制 | `0D` / `D0` | 1 / 1 | 透传 1 字节设置值并校验回显一致 | 未启用 |

> **注**：原厂对 MCU ADC3 / ADC4 的换算公式为 `100000 / (3800 - raw)`，ADC5 直接使用原始值；内核 `sy108-mcu` 驱动通过 IIO 暴露 `raw` 原始采样值。

## 四、MCU 固件升级协议（Bootloader / LDROM）

原厂 FOTA 升级流程从 `/mnt/data/recovery/MCU_APP.hex`（Intel HEX 格式，上限 `0x40000` 字节）读取固件：

1. **进入 LDROM**：发送 9 字节切换帧 `AA 5A 09 00 09 00 00 00 16` 并等待应答。
2. **固定 64 字节升级帧格式**：

| 字节偏移 | 字段说明 |
|---|---|
| `0..2` | 固定帧头 `AA 40 00` |
| `3` | 升级命令码：`01`（START）、`02`（DATA）、`03`（STOP）、`5A`（RESET） |
| `4..5` | 请求帧固定填 `FF 01`；应答帧（6 字节）在偏移 `4` 返回状态码 |
| `6..9` | `DATA`：32 位小端目标写入地址；`STOP`：32 位 `ver_checksum` |
| `10..11` | `DATA`：16 位小端本帧数据长度 |
| `12..62` | `DATA`：数据内容（不足部分补 `0x00`）；`STOP`：偏移 `10..13` 为 32 位总长度 `hex_data_length`，偏移 `14` 固定 `0x5A` |
| `63` | 前 63 字节累加和低 8 位（`SUM8`） |

- **应答状态码（偏移 4）**：`00` = OK、`01` = CHECK_ERR、`02` = CMD_TYPE_ERR、`03` = UPGRADE_MODE_ERR、`04` = WRITE_DATA_ERR、`05` = UNKNOWN_ERR。

## 五、SC2730 PMIC Type-C 寄存器状态

通过 SC2730 ADI regmap 读取 `typec@380` 状态寄存器的实测值如下：

| 寄存器 | 偏移地址 | 实测读值 | 解析说明 |
|---|---|---|---|
| `TYPEC_STATUS` | `0x039c`（`0x380 + 0x1c`） | `0x00000000` | `STATUS[4:0] = 0`（`DETACHED_SNK`） |
| `TYPEC_DBG1` | `0x03e0`（`0x380 + 0x60`） | `0x00000100` | `DBG1[7:0] = 0x00` |

在外口正常连接主机并工作于 USB High-Speed NCM 模式下，SC2730 内部 Type-C 状态机保持 `DETACHED_SNK`（`0x0`），VBUS 接入事件由 `EIC0`（`extcon_usb0`）独立提供，与板载 CS32G020 接管外部 Type-C CC 引脚的硬件设计一致。
